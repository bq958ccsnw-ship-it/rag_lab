# Поиск релевантного контекста

## Каналы поиска

VirtHelp использует гибридный поиск. Векторный канал ищет семантически близкие фрагменты, а лексический канал BM25 учитывает совпадения слов и редких терминов. Результаты двух каналов объединяются методом Reciprocal Rank Fusion. PostgreSQL FTS остаётся резервным лексическим режимом и не включается третьим параллельным каналом.

В учебной конфигурации значение `top_k` по умолчанию равно пяти. Увеличение `top_k` обычно повышает вероятность найти релевантный источник, но одновременно добавляет нерелевантный контекст и расход токенов. Поэтому лучшее значение выбирают по размеченной dev-выборке.

## Реранжирование и расширение контекста

После первичного поиска может применяться модель `bge-reranker-v2-m3`. Если реранжировщик недоступен, система сохраняет ограниченный порядок объединения и отмечает режим fallback; область доступа пользователя при этом не расширяется.

Для найденного опорного фрагмента система может добавить соседние фрагменты с номерами `seq_no ± 2`. Такое parent-child расширение выполняется только внутри той же активной версии документа. Оно даёт генератору связный контекст, но не меняет исходный retrieval rank опорного фрагмента.
